# استراتيجية الاختبار

## ما تم تشغيله فعليًا (Node.js — بدون أي إعداد إضافي)

جميع منطق التحليل (`js/core`, `js/url`, `js/engine`, `js/domain`,
`js/app`) مكتوب كوحدات ES Module خالية من أي اعتماد على DOM، لذلك يعمل
مباشرة داخل Node.js دون أي Bundler أو محاكي متصفح. تم تشغيله فعليًا عبر:

```bash
node --test tests/*.test.js
```

**النتيجة الفعلية المُنفَّذة**: 89/89 اختبارًا ناجحًا، 0 فشل. (التفاصيل
الكاملة في التقرير النهائي المرفق مع هذا التسليم، متضمنة الأمر الدقيق
والمخرجات).

### تغطية الاختبارات:

- `tests/url.test.js` (32 اختبارًا): Validator (فارغ، طويل جدًا، أحرف
  تحكم)، Normalizer (إضافة scheme، رفض `javascript:`/`data:`/`file:`،
  الحفاظ على query params دون تغيير، منافذ غير معتادة، IDN/Punycode)،
  Canonicalizer (إزالة www، كشف Punycode)، SsrfGuard (17 اختبارًا:
  localhost، كل نطاقات IPv4 الخاصة، metadata endpoint، IPv6
  loopback/link-local/unique-local، IPv4-mapped IPv6).
- `tests/risk-engine.test.js` (11 اختبارًا): حتمية النتيجة (50 استدعاء
  متطابق بالضبط)، سياسة القرار المحافظة (لا Green بدون دليل)، عدم
  استخدام لغة "100%"/"مضمون"، مؤشر التحويلات يُقر صراحة أنه يحتاج
  Backend.
- `tests/mock-engine.test.js` (15 اختبارًا): مسارات نجاح (Green/Yellow/
  Red فعلية عبر أمثلة حقيقية)، فشل (فارغ، غير صالح، مخطط غير مدعوم)،
  رفض SSRF (localhost، IP خاص، metadata) كفشل صريح وليس درجة خطر، إلغاء
  قبل البدء وأثناء التنفيذ، حتمية عبر التحليل الفعلي الكامل، رابط طويل
  جدًا، وتأكيد عدم تسرّب المدخل الخام داخل النتيجة المُسلسلة (JSON).
- `tests/live-engine.test.js` (5 اختبارات): يفشل دائمًا بدون provider،
  لا يُنتج Green أبدًا لأي مدخل، غير قابل لإعادة المحاولة تلقائيًا في
  Mock صامت.
- `tests/core-services.test.js` (21 اختبارًا): TemporaryCache (تخزين/
  انتهاء صلاحية/إخلاء)، SecureLogger (تنقية روابط وبريد إلكتروني من
  النصوص)، StorageService (لا حقل url في السجل مطلقًا، حذف فردي، حذف
  الكل، حد أقصى 200 عنصر)، FeatureGate (حدود Free/Premium).
- `tests/analysis-controller.test.js` (10 اختبارات، تكاملية): نجاح
  يُحفظ في السجل، فشل/إلغاء/SSRF لا يُحفظ في السجل، Mock يعمل حتى مع
  "Offline" مُحاكى (لأنه لا يحتاج شبكة)، Live+Offline يعطي خطأ Offline
  وليس Green، Live+Online يعطي Provider Unavailable، تعدد Controllers
  مستقلين (لا Singleton مشترك)، حد الاستخدام اليومي.

## ما لم يُشغَّل فعليًا (Blocked by Environment)

- **اختبارات المتصفح الفعلية (رسم DOM، النقر، الكاميرا الحقيقية)**: بيئة
  التنفيذ الحالية لا تملك متصفحًا مثبَّتًا (Playwright مثبَّت كحزمة
  لكن بدون ملفات المتصفح الثنائية Chromium/WebKit — تحميلها يتطلب
  اتصال إنترنت غير متاح هنا). لذلك `js/main.js`, `js/ui/*.js`,
  ملفات HTML الخمس لم تُختبر آليًا بمحرك عرض حقيقي — **روجعت يدويًا
  بعناية بدلاً من ذلك** (انظر قسم "المراجعة اليدوية" أدناه).
- **اختبارات الكاميرا الحقيقية / أذونات المتصفح**: تتطلب جهازًا فعليًا
  ومتصفحًا حقيقيًا؛ لم تُختبر تلقائيًا.
- **Production build فعلي عبر أداة**: لا توجد خطوة بناء أصلاً (Vanilla
  JS بدون Bundler) — لذلك "الـBuild" هنا هو نسخ الملفات الثابتة كما هي
  إلى `dist/`، وليس تجميعًا (compilation) بمعنى Webpack/Vite.

## المراجعة اليدوية (بديل عن اختبار المتصفح الآلي)

تمت مراجعة `index.html` مقابل `js/main.js` برمجيًا (سكربت Python) للتأكد
من أن كل `id`/`class` يستدعيه JavaScript موجود فعليًا في HTML — النتيجة:
تطابق كامل بدون أي عنصر مفقود. كما رُوجعت يدويًا: تسلسل الشاشات، مسار
onboarding، مسار QR الكامل (دعم/عدم دعم/رفض إذن)، مسار الإلغاء، مسار
إعادة المحاولة، حذف عنصر فردي وحذف كامل السجل.

## اختبارات الأمان (ضمن مجموعة الاختبارات أعلاه، مُنفَّذة فعليًا)

محاولات SSRF (localhost، كل نطاقات IPv4/IPv6 الخاصة، metadata endpoint)،
حدود النطاقات الصحيحة (172.15.x و172.32.x لا يُرفضان خطأً)، روابط طويلة
جدًا، مخططات خطرة (javascript:/data:/file:)، روابط مشوّهة، حالات
Unicode/Punycode.
